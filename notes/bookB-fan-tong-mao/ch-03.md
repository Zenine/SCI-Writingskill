# 书B 第3章 构思学术故事线

> 来源:书B 第3章(书页 44–64,PNG bookB-058–078)

## 核心主张(3–7 条,自己的话)

1. "故事线意识"(storyline)是与伦理意识、读者意识并列的三大写作基础意识之一;它不是让论文变得煽情,而是要求论文有一条清晰的逻辑脉络和叙述过程。任何学科(含数学、计算机、理论物理)都需要,只是"有趣"的成分可以少,"有逻辑"的成分不能少。
2. 同一组数据可以讲出多个故事;一篇论文通常只能讲清一个。选哪个故事,由作者团队的学科背景、目标读者和目标期刊共同决定,必须在动笔前与合作者达成一致。
3. 学术故事与普通故事的根本区别在于**必须完整**:从数据 → 信息 → 新知识 → 新理解四级递进,缺一不可。多数被拒稿的文章停留在前两级,没说清给学科贡献了什么新知识、新理解。
4. 中国作者最常见的短板是不敢/不会说自己研究的原创价值,尤其是结论(conclusion)写不好。再小的进展也要在结论里说明它可能带来的后续改进。
5. 故事的"大小"决定目标读者与期刊层级:大故事(广泛适用、多国大样本验证)面向 Nature/Science 级别的广泛读者;小故事(特定机制、特定受体)面向细分领域专家。大小都有价值,但不能错配期刊。
6. 学术故事讲不通时不要硬讲,数据里往往藏着另一条更好的故事线(Alvarez 从板块旋转 → 地磁反转 → 恐龙灭绝的科研生涯就是例证)。
7. 故事线能力靠日常训练:写论文前做 20–30 分钟研究汇报、带着故事线意识"刻意阅读"文献、用思维导图画讲者的叙述线、对着一张图跟合作者讲小故事。

## 结构模型 / 模板

### 1. 故事六要素 ↔ 论文三段(3.2)

好故事有六个要素:人物、背景、张力、动作、高潮、结局。作者用"龙头、猪肚、凤尾"的中学作文比喻映射到论文:

| 作文比喻 | 论文部分 | 承担的故事功能 |
|---|---|---|
| 龙头 | 背景 + 科学问题 | 建立情境和张力(为什么这个问题值得解决) |
| 猪肚 | 方法、发现、讨论 | 动作与高潮(怎么做、发现了什么、意味着什么) |
| 凤尾 | 结论 | 结局(对最初问题给出判断) |

判断标准:能否用一句话说出"张力"(前人认为 X,但我们发现 Y);如果只有"动作"没有"张力",就只是数据报告。

### 2. 起点:学科背景决定故事(3.3)

案例:一张"父亲扛着儿童自行车走在北京街头"的照片,不同专家会提出完全不同的问题——社会学家问父亲育儿参与度、生物学家问年轻父亲是否早衰、犯罪学家问儿童自行车被盗是否增加。同一"结果"(照片)承载多个故事,选择哪个由提问者的知识储备驱动。
- 推论一:讲好学术故事的第一步是问自己"我具备哪种讲故事的条件",基于最擅长的学科背景讲。
- 推论二:背景知识也会误导(照片主角其实是作者本人,不是小偷)——要警惕先入之见,用学科知识客观审视数据。
- 第二个案例(在线课程完课率只有 5%):机器学习背景的人会做预测算法,教学法背景的人会分析教学设计环节,动机心理学背景的人会做问卷剖析动机——故事线贯穿研究设计、实验开展、数据分析全过程,不是写作阶段才出现的。

### 3. 完整性模型:数据 → 信息 → 知识 → 理解(3.4)

以 Watson & Crick 1953 年 DNA 论文为范本:

| 层级 | 含义 | DNA 案例 |
|---|---|---|
| 原始数据 | 实验/观测直接产出 | Franklin 与 Gosling 的 X 射线衍射照片"51 号" |
| 数据表达的信息 | 从数据中解析出的事实 | 原子在大分子中的位置(碱基、糖、磷酸的位置) |
| 新知识 | 把信息组织成新的模型/规律 | 双螺旋三维模型(推翻此前的三螺旋假设) |
| 新理解 | 新知识如何改变我们对世界的认识 | 碱基配对结构直接暗示了遗传物质的复制机制 |

- 关键判断:如果论文停在"新知识"(双螺旋结构),它不会成为 20 世纪最重要的论文之一;使它伟大的是最后一步"新理解"。原文中那句以 "It has not escaped our notice that …" 开头的名句,就是用一句话完成从知识到理解的跳跃。
- 大多数论文只是细分领域的渐进进步,但作者坚持:任何发现无论多小,都应该有完整的四级故事。

**动笔前四问自检**(可直接做检查表):
1. 我收集的数据是什么?
2. 我从数据中掌握了什么信息?
3. 我发现了什么新知识?
4. 我给学科贡献了什么新理解?
答不出第 4 问,说明故事不完整,不宜动笔。

### 4. 选择:从多条故事线中挑最有趣的(3.5)

案例:2016 年 Science 上关于家犬双重起源的论文(9 国十几所大学、多学科团队)。同一批发现可以拆成三条候选故事线:

| 候选故事 | 依托的发现 | 核心价值 | 目标读者 |
|---|---|---|---|
| 方法论故事 | 用 SNP + MSMC 等技术重建犬种群历史 | 方法本身的价值与可迁移性 | 想用类似方法的研究者 |
| 起源故事 | 东亚狗与西欧亚狗基因深刻差异、出现时间 | 理解狗如何从狼驯化演变 | 关心狗起源的研究者与大众 |
| 迁徙故事 | 古代欧洲狗与现代欧洲狗单倍型不连续 | 从狗的迁徙推测人类迁徙 | 考古与人类学研究者 |

团队最终选择"起源故事",理由有二:(a)它回答了一个很多人关心的有趣问题;(b)它**推翻了主流认识**(狗只被驯化过一次)——与双螺旋推翻三螺旋同构,同时提供新知识和新理解。

**选故事线的判断标准**(从案例归纳):
- 是否回答一个尽可能广泛的读者会关心的问题;
- 是否修正/推翻既有认识,而不只是补充细节;
- 是否有扎实数据支撑(有趣≠猜测);
- 目标读者与期刊是否与故事大小匹配;
- 剩余的故事线不是作废,可以由不同作者按各自兴趣组织成另外的文章。

### 5. 拓展:科研生涯本身也是故事线搜索(3.6)

Alvarez 的路径:板块旋转假说(证据不足,放弃)→ 岩石样本中磁罗盘反向 → 地磁极性反转史 → KT 边界上方无有孔虫化石 → 灭绝时间恰逢恐龙消失 → 陨石撞击致灭绝说。启示:一条故事线讲不通时,放弃它并留意数据中的"异常",那里可能有更大的故事。

### 6. 常见问题答疑(3.9)要点

- **导师给了思路但写不出来**:核心原因是构思阶段自己没参与。三步补救:先"听懂"(动机、出发点、创新点,敢于提问);再"讲出来"(写作前做 20–30 分钟研究汇报,让导师和同事听懂你的故事,否则写完 6000 字才被说逻辑不对);最后"学会学"(记录导师如何讲故事、如何描述创新点、如何决定投哪个期刊)。研究生要把自己当研究设计者,不是"科研民工"。
- **数学/计算机这类学科讲不出故事**:故事线意识要求的是有逻辑的故事而非有趣的故事。数学论文至少在摘要、引言、结论让非本专业读者读懂做了什么、有什么价值,例如在引言交代猜想的历史脉络。计算机论文常是增量改进(减内存、降功耗),要讲出这个增量最终对应用/领域的影响(如人脸识别毫秒级响应),而不是只重复算法本身。
- **日常如何提升**:认真做实验室汇报;读文献时用颜色标出数据/信息/知识/理解四个成分("刻意阅读");听报告时用思维导图画讲者的叙述线并思考换你怎么讲;读报纸漫画时练习看图讲故事;拿一张实验数据图跟合作者讲一个小故事——大文章就是小故事的拼图。

## 语法与语言要点

本章不涉及。

## 高频通用短语(英文,按功能分组,每组 ≤ 8 条)

本章主要是方法论,英文短语较少;以下从案例与练习文本中提取的通用骨架:

**从知识跳到理解(点明 implication)**
- It has not escaped our notice that …
- … immediately suggests a possible mechanism for …
- … provides a new understanding of …
- These findings overturn the prevailing view that …

**建立张力(前人观点 vs 本文发现)**
- It was widely accepted that … only once.
- The only debate was whether … occurred in A, B or C.
- However, no evidence supports this assumption.
- An alternative hypothesis, that …, is more plausible.

**练习文本中的故事开头句式(背景 → 挑战 → 突破)**
- The … in [year] of … was seen as a significant milestone in …
- An even greater challenge remained — …
- Despite decades of refinement, until recently … were still …
- This is the first time that … has …

**描述发现(练习中的摘要句式)**
- Genomic and archaeological evidence suggest …
- … uses/relies on … for orientation
- … fails to … without …

## 可直接转化为 skill 规则的条目(每条一句,可检查)

1. 动笔前必须用"数据 / 信息 / 新知识 / 新理解"四问自检,第 4 问答不出则先补构思再写。
2. 每篇论文只讲一条主故事线;若数据支持多条,选定一条并在提纲中写明其余故事线的去向(另文或舍弃)。
3. 故事线必须在写作前与所有合作者书面确认(可以用一句话故事陈述 + 二级标题清单作为载体)。
4. 故事线陈述必须包含"张力":用一句话写出"前人认为/已知 X,本文发现/表明 Y"。
5. 故事的大小必须与目标期刊读者面匹配:投综合性顶刊要能说明对广泛读者的意义,投专业期刊要说明对细分领域的意义。
6. 结论部分必须明确写出新理解与原创贡献,即便进展很小也要说明可能带来的后续改进;不得只重复发现。
7. 引言必须交代问题的演变脉络(前人工作 → 未解之处 → 本文切入),即使是数学、计算机等"无故事"学科。
8. 增量型技术论文必须写出增量对应用或领域的最终影响,不得只重复算法/系统本身。
9. 摘要、引言、结论三处必须让非本专业读者能读懂做了什么、有什么价值。
10. 写作前建议做一次 20–30 分钟的口头研究汇报,以合作者能复述故事线为通过标准。
11. 审阅稿件时,若讨论/结论停留在"数据 + 信息"层级(只描述结果、不说明知识与理解),判定故事不完整。
12. 警惕先入之见:故事线必须由数据支撑,不得因"背景常识"跳到未经验证的解释。

## 疑问 / 与书A可能冲突处

- 书B用"故事线/张力"框架,书A用"信息结构模型"(引言、方法、结果、讨论各单元的功能句序)。两者不冲突:书B回答"讲什么、为什么讲",书A回答"每部分按什么顺序写"。合成 references 时可把书B的四级完整性作为全文层面的检查,把书A的模型作为分节层面的检查。
- "新理解"(understanding)在书B是独立的第四级,书A讨论单元里的"implication / 与前人关系"部分与之对应,但书A没有把它作为拒稿判据;skill 里是否把"缺新理解"定为硬性不通过,需要与书A的口径统一。
- 书B强调"一篇论文一条故事线";书A未明确禁止多主线,但其引言模型隐含一个研究目标。建议 skill 采用书B的硬规则。
- 书B主张摘要/引言/结论应让非专业读者读懂;书A更强调面向同行专家的精确性。两者对"读者"的默认设定不同,skill 需要按目标期刊类型分档(综合刊 vs 专业刊)。
- 本章英文短语很少,且多来自已发表论文(Watson & Crick、AlphaGo、粪甲虫),笔记只保留骨架;实际短语库应以第 4 章及书A为主。
- 书中"Alvarez 1980 年代提出陨石撞击说"与"6300 万年前恐龙灭绝"是叙述简化(一般表述为约 6600 万年前),笔记不复述数字细节,避免把科普简化带进 skill。
