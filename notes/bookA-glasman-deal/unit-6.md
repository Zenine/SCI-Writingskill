# 书A 第六单元 怎么写摘要

> 来源:书A 第六单元(PDF 页 400–449;正文自 402 页起)

## 核心主张(3–7 条,自己的话)

1. 摘要是论文中被读得最多的文本,它决定研究是被看见还是被忽略。网络阅读环境下摘要早已不是论文的"序曲",而是被单独访问的独立文本,读者目的各异(看动态、查细节、查是否撞题、直接据此做临床决定)。
2. 每年数百万篇论文在争夺注意力,连续快速浏览多篇摘要的读者需要"极高的清晰度和连贯性";作者因为熟悉内容总觉得自己写得清楚,这是最大的盲区。
3. 清晰度的技术含义是可操作的:明确认领贡献、消除指代词歧义、术语前后一致、句子短(平均约 22 词,超过 40 词的句子只有一成读者一次读懂)、用句首技巧引导叙述。
4. 字数上限不是目标。塞满上限只会稀释关键信息;摘要不必是全文概览,要优先呈现核心成就或贡献并明确发信号。
5. 摘要最后写,在论文其余部分完成后;它不是"创作"而是从论文里"挑选",投稿前还要按目标期刊要求重新对齐。
6. 摘要中的含义强度必须与正文数据一致;可以比正文表述得稍强以吸引读者,但不能误导。早期阶段或潜在价值用 could / may / potential 标示。
7. 摘要语言要照顾全球读者、跨学科读者和快速读者:简单、传统、少缩写;缩写必须用,则给一次全称。

## 结构模型 / 模板

### 四种摘要类型及模板差异

| 类型 | 形态 | 模板差异 |
|---|---|---|
| 1. 简单/一般摘要 | 单段,80–250 词 | 完整走通用模板 3 大块 9 个组件,由作者用句首短语自行分段 |
| 2. 结构化摘要 | 带小标题(Background / Objective / Approach / Methods / Results / Significance / Conclusions 等) | 组件与小标题一一对应,小标题替代了叙述性过渡;各块内部仍按"事实 → 问题 → 本文做了什么"微结构写 |
| 3. 摘要 + 重要性说明 / 亮点 | 摘要之外另附 Significance 段或 3–5 条 Highlights 要点 | Significance 面向跨学科读者,重讲"为什么重要 + 本文发现 + 更广影响";Highlights 是每条一句的成就/结果/含义清单;两者是摘要的附件而非补充,PDF 中可能不出现,不能承担摘要本身的功能 |
| 4. 图形摘要(Graphical Abstract) | 单幅图,可带短文本 | 只呈现一个关键信息,颜色克制、去杂乱;图可取自正文或专门设计;常与 Highlights 一同出现 |

### 通用摘要模板(9 个组件,分 3 块)

第一块:为什么 + 做了什么
1. **主题重要性 / 基本事实背景**——一句到两句,只在读者理解摘要必需时给。一般现在时。
2. **挑战 / 问题**——文献中的缺口、现有方法的缺陷、争议。一般现在时或现在完成时;常用 however / despite / little work 转折。
3. **论文/研究做了什么**——可与成就合并("本文提出一种新方法,达到……")。一般现在时(This paper presents / Here we show)或现在完成时(We have developed)。

第二块:怎么做 + 得到什么
4. **方法 / 材料**——只给决定读者是否读全文的关键信息(模拟还是实测、单案例还是系列实验),可带关键数字。一般过去时为主。
5. **结果 / 与已有结果比较**——关键结果,常配数字;数字要有语言限定(only、as high as)以防误读。一般过去时或一般现在时(摘要中常用现在时以增强即时感)。
6. **含义**——用 suggest / indicate / appear to。一般现在时。

第三块:意味着什么
7. **映射已有知识**——比较、扩展、纠正。
8. **成就 / 价值 / 贡献**——几乎每篇摘要至少一句,常带"快乐词汇"(first、novel、robust、practical)。现在完成时或一般现在时。
9. **应用**——broad application / suitable for / will enable。一般现在时 + 情态动词。

作者标出多个组件可插入"快乐词汇"的位置,提示价值可以在做了什么、方法、结果、映射、贡献、应用等多处反复发信号。

### 字数受限时的合并技巧

- 论文做了什么 + 成就:一句同时说"提出了 X"和"达到了高精度/鲁棒性"。
- 成就 + 空白:"它解释了此前无法解释的一系列观测"。
- 方法 + 结果:"加入 ≥ 某剂量的 X 导致显著抑制"。
- 成就 + 含义:结果句尾接 suggesting that ... 分词结构。
- 用第一单元的句间衔接技巧检查每两句之间的"缝隙"读者能否轻松跨过。

### 摘要自检清单(书中 6.5 节的逆向工程项目)

与通用模板的偏离度;方法与结果所占比例;第一句功能;"快乐"语言数量;降风险语言;主要成就如何被优先;每句时态及理由;时态/被动是否造成归属歧义;this / it 是否歧义;平均句长;哪些缩写可取;关键信息是否明确。

## 语法与语言要点

### 认领贡献(与第五单元同源)

一般现在时 + 非人称主语的句子(如"理论建模表明……")读起来像公认知识,读者分不清那是背景还是你的结果。三个手段:

1. 用一般过去时或现在完成时(showed / has shown);
2. 用主动语态 we;
3. 句首加归属短语:背景句用 it is known that 一类标记(或 previously demonstrated),本文句用 in this study、here 开头。

作者的说法值得记住:目标不是让读者"能够"理解,而是让读者"不可能不"理解并认出你的贡献。

### 时态分工

- 论文里有什么 / 本文做了什么:一般现在时为主。
- 方法(已经做了什么、用了什么):一般过去时为主。
- 结果与含义:过去时或现在时皆可;摘要里常用现在时以制造即时感,即使正文用过去时。
- 成就/价值/贡献:现在完成时或一般现在时。
- 背景事实:一般现在时本身就在传达"这是公认事实"。

### 指代与一致性

- this / it / which 后面补名词或重复名词短语;书中一篇 140 词的摘要把方法名重复了至少四次,这是刻意的。
- 同一事物全篇只用一个名字:approach 不要变 scheme,model 不要变 method,tool 不要变 device。
- 数字旁边加限定语(only、as high as、up to),避免读者误判方向。

### 句长与可读性

- 20 词以下的句子九成读者一遍读懂,40 词以上只有一成;书中 18 个样本摘要平均 22 词/句。
- 缩写:编辑不喜欢满是缩写的摘要;确需使用则首次给全称。
- 引用:摘要通常不含引文;只有当论文直接源于、显著改进或与某篇已发表工作矛盾时才引用。

## 高频通用短语(英文,按功能分组)

**背景与重要性**
- ... is fundamental to / central to ...
- ... is known to / is widely accepted to ...
- ... is regarded as ...
- It has recently been shown that ...
- ... plays a key role in ...
- ... is widely exploited to ...
- ... remains poorly understood

**挑战 / 问题**
- However, ... remains a significant challenge
- Despite this, little work has been undertaken to ...
- ... is the subject of intense current debate
- ... has proved to be a difficult problem
- Existing methods are limited by / time-consuming / inaccurate
- There is a need for ...
- Until now, ...

**本文做了什么**
- This paper presents / describes / reports ...
- Here we introduce / propose / demonstrate ...
- In this study, we investigate / examine / attempt to define ...
- We report herein ...
- We have developed and implemented ...
- This study aims to quantify / compare ...

**方法与结果**
- ... was measured / analysed / evaluated using ...
- Two types of ... were examined
- Rather than / Instead of / Unlike ...
- ... resulted in / led to / reached up to ...
- ... was observed / identified / obtained
- ... reveals / exhibits / demonstrates ...
- Statistically significant ... were observed

**含义**
- These findings indicate / suggest that ...
- The data collectively suggest that ...
- ... appears to / seems to ...
- It was concluded that ...
- ... may act as a possible ...
- ... is likely to ...

**成就 / 价值 / 贡献**
- the first ... / a novel ...
- ... provides direct evidence for ...
- ... improves upon the accuracy of existing ...
- ... outperforms several recently proposed methods
- ... is both realistic and flexible
- ... robust and practical
- ... fills key gaps in ...

**应用**
- ... has broad application to ...
- ... constitutes a general design principle for ...
- ... is suitable for / relevant for ...
- ... will enable the design of ...
- ... has considerable potential for use as ...
- ... should find a wide range of applications in ...

## 可直接转化为 skill 规则的条目(每条一句,可检查)

1. 摘要在正文全部定稿后再写,且投稿前按目标期刊格式(一般 / 结构化 / 附 Highlights / 图形)重新对齐一次。
2. 摘要先确定唯一的核心贡献并在"本文做了什么"句中明确发信号,不得平均罗列所有成果。
3. 摘要每个陈述本文发现的句子必须带归属标记(过去时/现在完成时、we、this study、here / in this paper 之一);背景句用 it is known that 一类标记与之区分。
4. 摘要中 this / it / which 若可指向两个以上先行词,必须补名词。
5. 同一对象在摘要中只用一个名称(method / model / approach / system 不互换)。
6. 摘要平均句长 ≤ 25 词,单句不超过 40 词。
7. 摘要中的缩写:首次给全称;若全篇只用一两次,不缩写。
8. 摘要默认不含引文;只有直接继承、显著改进或反驳某篇具体文献时才引用。
9. 方法信息只保留读者决定是否读全文所需的部分(模拟/实测、单案例/系列实验、关键条件),数字旁加限定语。
10. 摘要中的含义强度不得超过正文数据支撑;早期或潜在价值必须用 could / may / potential / possible 标示。
11. 摘要至少含一句明确的成就/价值/贡献句,可用 first、novel、robust 等评价词但须有结果支撑。
12. 字数超限时优先合并功能(做了什么 + 成就、方法 + 结果、结果 + 含义),而不是删掉衔接词。
13. 结构化摘要各小标题下不得留空,且各块内容不互相重复;Highlights 每条一句、不超过期刊规定条数、不复制摘要原句。
14. 摘要第一句只能是背景事实、问题或"本文做了什么"三者之一,不得以方法细节开头。
15. 摘要写完后过一遍 6.5 节清单:第一句功能、时态理由、归属歧义、指代歧义、句长、缩写、关键信息是否可一眼找到。

## 疑问 / 与书B可能冲突处

- 书A允许摘要中结果与含义用一般现在时(比正文更"即时"),书B若规定摘要结果一律过去时,按更可检查的规则取书B,但在 reference 中注明书A的例外。
- 书A主张摘要可以适度用"快乐词汇"和 first / novel;中国作者常被告诫少用 novel,skill 需加"必须有对比数据支撑"的条件。
- 书A把 Significance / Highlights 视为摘要的附件、独立撰写;书B若把 Highlights 当摘要的浓缩版,处理方式不同。
- 书A对摘要长度只给 80–250 词区间和"看目标期刊",没有硬阈值;书B可能给出更具体的字数或句数建议。
- 书A的"方法可用被动"与"用 we 认领贡献"并存,skill 需明确:方法句可被动,贡献句应主动或加归属短语,避免用户误以为二选一。
- 图形摘要部分书A只给设计原则,没有可检查规则;skill 中暂只放提示,等书B或期刊指南补充。
- 书A建议摘要中给数字加 only / as high as 等限定语,这与"摘要客观中立"的常见教学说法有张力,需在 reference 中说明理由(防误读而非渲染)。
