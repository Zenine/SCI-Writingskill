# 书A 第四单元 怎么写讨论

> 来源:书A 第四单元(PDF 页 298–370;正文自 300 页起,371 页为空白页)

## 核心主张(3–7 条,自己的话)

1. 讨论不是结果的复述,而是一段"向前推进的叙述":把读者从结果一步步、有逻辑地领到结论,并让读者带着一条明确的关键信息离开论文。
2. 动笔前先回答一个问题:这项研究的主要价值到底是什么——是方法更好、结果更准、改变了领域方向,还是开辟/扩展了应用?答案决定讨论的开头与主线,防止关键信息淹没在细节里。
3. 讨论与引言是镜像关系。引言由宽到窄(领域 → 文献地图 → 空白 → 本文),讨论由窄到宽(回顾本文 → 对空白的回应 → 定位到文献地图 → 面向外部世界的接口)。引言写了什么,讨论就要逐一回应什么。
4. 讨论的核心功能是"映射":把自己的工作放到已有知识地图上,说明是证实、扩展、修正还是推翻了前人结果。引文是定位工具,每条引文都要通过叙述说明它为什么出现在这里。
5. 语言的力度要与证据的力度匹配:既不能过度自信,也不能为了保险而一味用 may/might 压低自己工作的价值;时态和情态动词就是调节力度的旋钮,选错会成为审稿意见。
6. 大多数读者不按顺序读全文,标题、摘要、讨论/结论必须能独立成篇,所以讨论开头通常要么直接声明成就/贡献,要么"重启"读者(回顾背景、空白或关键结果)。
7. 局限性与未来工作不是自我贬低,而是给研究界一个明确的、可执行的接续课题,同时也为自己的后续工作和引用铺路。

## 结构模型 / 模板

作者从一篇 10 句的示范讨论中归纳出通用模板;顺序"上松下紧":靠上的组件多出现在开头,靠下的多出现在结尾,中间可以自由流动。各步骤的功能、信息流和常用时态如下:

1. **宣布本节结构/内容**(可选,在讨论里不常见)——告诉读者本节要谈什么。一般现在时。
2. **陈述研究的成就/贡献**——以"据我们所知,本研究是首个/最大的……"之类的开头确认对文献的贡献。注意用 to our knowledge 这类免责语,因为无法保证没有同类研究。一般现在时(贡献是当前有效的事实)。
3. **回顾背景/文献以"重启"读者**——重新定位那些跳读过来的读者。一般现在时叙述已被接受的事实;引用具体研究时可用一般过去时或现在完成时。
4. **回顾空白/目标/方法**——用与引言相同的措辞造成"回声",让读者立刻认出这是对引言问题的回应。不要为了文风换同义词(引言说 identify,讨论就仍说 identify)。
5. **回顾结果并探讨含义**——重复关键结果是允许的甚至必要的,但必须"延伸":说明它在已有知识背景下意味着什么、如何回应引言中的问题。描述本研究的发现用一般过去时;若认为发现足够可靠可作为普遍事实,则用一般现在时(见语法要点)。
6. **映射到文献/知识以比较或支持**——证实、扩展、矛盾、补充。这里引文最密集;可以首次引用此前未出现的文献,只要它与解释直接相关。
7. **指出局限性与未来工作**——局限多来自方法/结果中已提过的问题;但"需要进一步工作才能下结论"或"研究期间观察到的非正式证据"可在讨论中首次出现。未来工作用 should be investigated / would be of interest 之类的推荐语;注意区分"我们正在做"(work is underway)与"邀请他人做"。
8. **重申成就/贡献/影响**——收束叙述,呼应第 2 步。
9. **确定潜在应用**——为读者退出论文、把信息带回外部世界搭接口。用一般现在时 + 情态动词(could be implemented / may lead to)。

信息流总结:本文做到了什么 → 这在已知地图上处于哪里 → 还有什么没做到 → 对外部世界意味着什么。成就/贡献是最自由的组件,可在开头、结尾甚至全程反复出现。

作者还区分了"成就"(achievement,内向:引言提出的具体问题解决了没有)与"贡献"(contribution,外向:对知识或应用产生了什么影响),两者有时重合、有时需要分别陈述。

书中还给出一份逆向工程清单,用来分析目标期刊的讨论:第一句功能、与模板的偏离度、一般现在时背景句的数量与位置、结果复述所占比例、是否详细回顾方法、目标/空白与成果之间是否有明确连线、"快乐词汇"的使用、映射引文的数量、降风险语言的使用、局限性的位置与措辞。

## 语法与语言要点

### 时态:力度旋钮

- 用一般过去时描述本研究的发现 = "在我们的研究里是这样";改成一般现在时 = "这是一个独立于本研究的事实"。选哪个不能靠模仿目标文章,要作者自己判断数据够不够硬。
- 即使用了一般现在时,也可以用 often、appear to、in most cases 之类的软化词降低承诺。
- 建议练习:把目标文章讨论里的动词全部标出来,问自己"这个时态与结果的力度匹配吗"。
- 背景事实信息用一般现在时;自己的具体观察用一般过去时;对已有文献的概括常用现在完成时。

### 情态动词(modal verbs)用法分级

作者按"确定性程度"把科技写作中的情态动词分成六类功能,并强调:每类都有等价的非情态结构(it is possible that / is able to / is expected to),越来越多作者改用这些替代结构以避免歧义。

| 功能 | 现在 | 现在否定 | 过去 | 过去否定 | 替代结构 |
|---|---|---|---|---|---|
| 1. 能力 | can | cannot | could | could not | be able to / be capable of |
| 2. 可能(possibly) | may / might / could / can | may not / might not(**不能**用 could not / cannot,那是"不可能") | may have / might have / could have | may not have / might not have | it is possible that |
| 3. 预期(probably) | should | should not | should have | should not have | is expected to / is likely to / will probably |
| 4. 显然 / 不可能 | must | cannot | must have | cannot have / could not have | it is obvious that / it is impossible that |
| 5. 建议 | should | should not | should have | should not have | it is advisable to |
| 6. 必要 | must / need to / have to | do not need to / need not | needed to / had to | did not need to / need not have | it is necessary to |

确定性梯度(作者用"同事走路回家"的比喻):may/might/could(可能) < should(很可能) < must(显然) ;cannot(不可能)在最底端。

关键陷阱:

- **can 三义歧义**:一句 "X can occur" 可能是"有能力发生""有时发生"或"可能发生"。有歧义就换成 may、is able to 或 sometimes。can 最适合表达"选项/二选一"。
- **must 带有"无证据"的暗示**:说 must be 等于承认自己是推断而非观察;真有证据就直接用陈述句。
- **must not ≠ 不必要**:must not = 不允许;不必要用 do not need to / need not。
- **can not(分写)≠ cannot**:分写的 can not 只出现在 not only... 结构;cannot 是"不可能"。
- **could 双重含义**(过去的能力 / 假设的可能),要检查上下文是否会误读;不确定时用 was able to。
- **could have** 常表示"本可以但没有";**should have** 通常指没发生的事,**should not have** 通常指发生了的事。
- **should 两义**(预期 vs 建议)要靠上下文区分;ought to 与 should 同义但在科技写作中越来越少见。
- **did not need to**(不必要且没做)vs **need not have**(不必要但做了)。
- have to 偏口语,正式写作少用;might 比 may 更不确定,科技写作中不常见。
- 将来能力用 will be able to。
- 不要为了保险用 may/might/could;如果数据支持,升级到 highly likely / probable / almost certain。

### 引文与措辞

- 引文数量参考目标期刊讨论部分的平均值;每条引文要有功能(比较、支持、解释机制)并通过句首短语把关系点明。
- 回顾前文时重复原词造"回声",不要为了避免重复而换词。
- 表达价值的"快乐词汇"分两级:普通肯定词(robust、reliable、efficient、novel、straightforward)和"感叹号替代词"(unprecedented、striking、remarkable、compelling),后者是科技写作里表达"哇"的合法方式,但要有数据撑腰。

## 高频通用短语(英文,按功能分组)

**映射到文献 / 比较**
- consistent with / in line with / in agreement with
- in contrast to / contrary to / unlike
- comparable to / analogous to / similar to
- to the best of our knowledge
- previously reported / recently described
- These results corroborate / extend / challenge ...
- This study complements / builds on ...
- Our data provide support for ...

**推测与含义(降风险)**
- It is conceivable that ...
- It is reasonable to assume that ...
- We postulate / hypothesise / speculate that ...
- A tentative explanation is that ...
- This points to ...
- We cannot rule out ...
- This is reinforced / substantiated by ...

**成就与贡献**
- This work provides a first step towards ...
- ... provides a framework for / insight into ...
- ... removes the need for ...
- We were able to demonstrate ...
- The approach presented here enables / allows ...
- ... outperforms / compares well with ...
- ... offers a robust / cost-effective / straightforward means of ...

**局限与未来工作**
- Further work is needed to ...
- Future studies should investigate / validate / replicate ...
- It would be of interest to ...
- ... should be explored further
- Work is currently underway to ...(仅指作者自己正在做)
- A promising direction is ...
- Recommendations for future studies include ...

**应用**
- ... is applicable to / suitable for ...
- ... could be implemented / generalised / extended to ...
- ... holds promise for ...
- ... may eventually lead to ...
- ... provides evidence-based guidance for ...
- ... could serve as ...

## 可直接转化为 skill 规则的条目(每条一句,可检查)

1. 写讨论前先用一句话写出研究的主要价值类型(方法 / 结果 / 改变方向 / 应用),讨论第一段必须围绕它展开。
2. 讨论第一句只能是两种之一:声明成就/贡献,或回顾背景/空白/关键结果以重启读者;不得以"本节讨论……"之类的空泛陈述开头(除非目标期刊惯例如此)。
3. 引言里的每个空白/目标在讨论里必须有一处明确回应,且使用与引言相同的关键动词和名词。
4. 声称"首个/最大/唯一"时必须加 to our knowledge 一类免责短语,并在投稿前重新检索。
5. 每条引文所在句必须通过句首或句中短语(consistent with、in contrast to、as reported by 等)说明该引文与本研究的关系。
6. 讨论中复述关键结果时,同一句或紧邻句必须给出含义或解释,不允许只复述不延伸。
7. 描述自己发现的句子默认用一般过去时;改用一般现在时前必须能说明数据足以支撑为普遍事实。
8. 检查每个 can:若可被读成"可能/有时/有能力"三义中的两义以上,替换为 may、is able to 或 sometimes。
9. 检查每个 must:表示推断时改用 it is obvious that 或直接给证据;表示"不必要"时禁止用 must not。
10. 表示"可能不"只能用 may not / might not,不能用 cannot / could not(它们表示"不可能")。
11. 若结果强而语言弱(满篇 may/might),升级为 likely / probable / almost certain;若结果弱而语言强,降级并加软化词。
12. 讨论至少包含一处局限性和一处未来工作;未来工作要具体到可执行的课题,并区分"我们正在做"与"建议他人做"。
13. 讨论结尾必须有一句面向外部世界的收束(重申贡献或指出应用),不得以局限性收尾。
14. 引言中未出现的文献可在讨论中首次引用,但仅限于解释机制或应用高度相关的情形。

## 疑问 / 与书B可能冲突处

- 书A认为讨论可以、通常也应该复述关键结果;书B(面向中国作者)可能更强调"讨论不重复结果",需核对书B相应章节后在 reference 中注明两说。
- 书A主张开头就声明贡献是"日益增长的趋势",但同时说要看目标期刊;skill 中应把它写成默认选项而非硬规则。
- 书A鼓励 unprecedented / striking 这类强词,而许多中国作者的写作教程主张克制;需在 skill 中加"必须有数据支撑"的前提。
- 书A把"用一般现在时陈述发现"视为作者自主决定,书B若给出更机械的时态规则(如结果一律过去时),按"更可检查的规则"取书B,并注明书A的例外情形。
- 情态动词替代结构(it is possible that)在书A中被视为更安全的趋势;若书B主张多用情态动词以求简洁,两者需权衡。
- 局限性可在讨论首次出现的条件(非正式证据、需进一步工作)书A讲得较松,书B可能要求局限性集中放在固定位置。
